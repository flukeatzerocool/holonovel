## 2. Rules

**Citations.** For each REQ body from `extractReqBodies`, take the text from the
**last** `*Check:*` or `_Check:_` marker to the end of the body **as
`extractReqBodies` returns it** — note it is *not* trimmed at `\n---\n` the way
`extractReqBodiesWithSentences` (`scripts/lib/parse-spec.ts:192-193`) is, so
trailing prose can contribute tokens and the measured 122 assumes exactly that.
Collect every `\bT\d+[a-z0-9]*\b` token (T only; `S`/`I` are out of scope),
de-duplicate within the REQ, key by the id as written (`REQ-284f`).

**Kind.** `cells[2].trim()`; `desc` stays raw `cells[3]` (its only consumer
matches `\bTTRPG_[A-Z0-9_]+\b`, which ignores the padding). Duplicate T-IDs keep
the **last** row (today's behaviour) so `:1725` sees unchanged text.

**Verdicts.** `Automated` + ID not exercised → `automated-unexercised`;
`Manual` + ID not matched `\b<id>\b` in `DECISIONS.md` → `manual-undocumented`;
no row → `no-row`; kind outside `{Automated, Manual}` → `unknown-kind`.

**Record shape.** `LinkageFinding` — `{ reqId: string; tid: string; kind: string; verdict:
"automated-unexercised" | "manual-undocumented" | "no-row" | "unknown-kind" }`.
`kind` is the raw trimmed cell, so an `Automated`/`Manual` value narrows the
verdict and any other value yields `unknown-kind`; it is `"none"` only for
`no-row`, and the corpus `kind` column prints it verbatim.
`--write-linkage-corpus <path>` writes one row per finding, so the corpus is
generated by the run.

**Absent `DECISIONS.md`.** The Manual rule is **skipped silently** — the same
idiom as `:1702-1707` — by passing `decisionsText: null`. It never re-labels 39
pairs as findings, and the skip is observable in the pure function, so case 7
can test it.

**Has-citation literal.** The two marker strings move to one exported constant in
`scripts/lib/req-checks.ts`, used by both the new extraction and `:2080`, so
"has a citation" cannot drift.

## 8. Risks

- **Parser edit feeds the coverage audit.** V2's bucket counts and
  `exercised test IDs: 685` are asserted literally; they are the guard.
- **V2's `= 10` is an equality on a capped print.** Increment 3 changes the
  corpus, so that row is expected to need an update then — failing loudly is the
  intent.
- **122 warnings is real noise** on every `validate` run. The print cap bounds
  the display; the corpus and register carry the list; increment 3 removes them
  by triage, not by suppression.
- **The Manual predicate is a proxy** (a bare `DECISIONS.md` mention passes), and
  the measured 122 assumes this session's extraction slice. V4 regenerates and
  diffs, so drift surfaces as a failing row rather than a silent adoption.
